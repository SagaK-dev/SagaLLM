# M2.5-a — prospective optimizer exposure journal

This introduces an opt-in CPU SFT step adapter and local journal. Existing historical training workflows and checkpoints are unchanged. The separate synthetic smoke runner exercises real forward/backward and AdamW updates, two checkpoint bindings, and trace verification. It is not a production training run or performance test.

Each journal is created exclusively. A header identifies the declared base checkpoint, tokenizer, dataset manifest, train split, seed, and bounds. A write-ahead intent records ordered domain-separated hashes of row IDs/families, exact encoded row input/label hashes, packed tensor digests (shape and canonical little-endian int64 bytes), and response target counts. The adapter checks actual packed row content/padding against encoded rows, then invokes forward/backward, clipping and optimizer.step. Only successful returns receive a completion event. Failed or interrupted steps remain unresolved; a partial write or failure poisons the writer. Every event is flushed and fsynced. Best/last checkpoint events bind serialized file SHA-256 and a journal prefix digest, and finalization requires a last checkpoint at the latest completed step.

The CPU smoke uses four project-created fixture examples, a freshly initialized small SagaTransformer, two actual optimizer steps, and two locally generated checkpoint files. It checks embedded checkpoint trace metadata using weights-only loading and publishes only the trace and smoke report. No Java compilation or execution. Tests cover a successful run, modified events, truncation, wrong batch/mask, duplicate file creation and optimizer failure. Best selection in the fixture is fixed and does not represent performance.

Limitations: local hash chains are not signatures or independent attestations; an attacker controlling the recorder could forge a consistent chain. A durable externally pinned trace digest/checkpoint digest and trusted execution provenance are needed. An optimizer return does not prove a specific example had nonzero gradient influence, nor that the update was atomic if recording failed. Hashed IDs and tensors can leak information by guessing and are not anonymization; keep real training journals private until reviewed. Header split and manifest labels alone are not proof of source membership. No historical exposure claim, no automatic resume, no distributed/mixed precision/gradient accumulation support in this adapter. Integration into the main SFT entrypoint, stronger source binding and signed external attestation remain future work. Do not change existing historical full training workflows just to test the adapter.
