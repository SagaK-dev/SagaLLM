# M2.5-c — integrated Java SFT optimizer exposure

The existing train_instruction_sft API now accepts record_exposure=True; CLI opt-in is --record-exposure. Default remains off. In the actual training loop the traced adapter records packed inputs before forward, optimizer returns after step, and every best/last save is bound to the corresponding journal prefix. It then verifies the final local chain, selected/last step, exact saved checkpoint hashes, embedded metadata, and replay against pinned TRAIN inputs before writing the successful training report. Validation/test loss scoring remains separate; initial structural corpus verification reads all splits, and TEST tokenization/scoring occurs after selection. No claim that the test bytes were never read. Incomplete/failed journal verification aborts the successful report. Journals contain hashes, not raw tokens, but are not anonymous.

The journal limit now permits best checkpoint replacement at every step; terminal last binding prevents subsequent steps or best overwrites. A zero-step selected best is valid. New dedicated CI exercises the existing full SFT entrypoint on a newly initialized small CPU fixture, two steps, the canonical synthetic corpus, and compile_cases=0. Only the report, trace and summary are uploaded, not weights. The old full v0.17/v0.18 training workflow jobs skip draft PRs and retain manual dispatch and non-draft PR paths (including ready_for_review); their existing command lines and artifacts remain unchanged. This avoids automatically launching long historical jobs for development drafts. No historical checkpoint used in this smoke, no generated Java execution, no model promotion or independent evaluation.

Local replay and checkpoint binding are not signed external attestations. No guarantee of actual gradient contribution, rights clearance, complete historical exposure or production quality. The report is not a public approval of arbitrary journals; raw source and journals from real training must be reviewed before publication.
