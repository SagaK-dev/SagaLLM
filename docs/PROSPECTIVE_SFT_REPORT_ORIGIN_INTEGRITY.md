# M2.5-f — SFT report source origin integrity

While integrating the prospective journal, we observed that the existing report derived its model-origin label solely from whether a context extension was requested. A freshly initialized local fixture could consequently be labeled PINNED_REAL_JAVA_V016 or PINNED_REAL_JAVA_V017_SFT even though pin enforcement was disabled. The #90/#91 smoke summaries correctly describe their fresh synthetic fixture base; their immutable historical train-report originals are not silently rewritten.

For future reports, distinguish enforced known historical pins, caller-supplied pins, and local checkpoints for which pin enforcement is disabled. The origin label is determined from the actual verified digest, not context length. Include the declared AdamW, learning rate, weight decay, gradient clipping, batch size, seed, evaluation cadence/counts and time-budget configuration. The offline verifier checks consistency of the new declarations with journal/header identities and evaluation-step history; old prospective reports remain verifiable but are labeled NOT_RECORDED for these additional fields. This is not proof of actual optimizer hyperparameters beyond the instrumented code, nor a rights or independent evaluation approval.
