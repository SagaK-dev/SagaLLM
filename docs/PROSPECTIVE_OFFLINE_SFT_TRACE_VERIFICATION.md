# M2.5-d — offline SFT trace verification

The verifier takes exact externally supplied report, trace-file and chain-tip SHA-256 pins. It rechecks the report scope, local chain, source replay, complete TRAIN admission and deterministic family-interleaved ordering, every packed batch, selected/last checkpoint byte digests and reported best-step threshold arithmetic. The verifier does not deserialize checkpoints, run model inference, or read validation/test rows. It does not recompute validation losses, check embedded checkpoint metadata independently, verify the original execution or certify gradient influence. The integration path checks embedded metadata when saving locally. The smoke runs two steps using the existing SFT entrypoint and a fresh small synthetic base, then runs the verifier before removing temporary inputs and weights. Only trace, report and metadata are published. A production audit must preserve approved inputs and exact externally pinned report/trace/checkpoint identities; a locally computed digest is not an independent attestation.

CLI: python -m scripts.verify_integrated_sft_trace --output RUN_DIR --dataset DATA_DIR --base BASE_PT --tokenizer TOKENIZER_JSON --report-sha256 REPORT_SHA --trace-sha256 TRACE_SHA --tip-sha256 TIP_SHA. No model promotion or rights approval.
