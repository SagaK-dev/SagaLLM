# SagaLLM 開発計画書

2026年11月24日策定。起点は `main` の `961130d684a459ee513e96d6be17511cb47315c8`。対象は172万パラメータのJava生成モデル。ゴールは、指示の意味に応じてコードを生成し、未学習の課題で期待する標準出力を返せるかを再現可能な方法で判定すること。

## 出発点

- v0.18のCPU学習は、PR由来と`main`手動実行の双方で400ステップ完了。検証損失で選んだbestは50ステップ。公開レポートはPR由来で、2回の重みのSHA-256は異なる。固定8題でコンパイルできたのはv0.17基準モデル2件、v0.18 best 0件。最終重みlastの生成成績は当時の原本に未収録。[学習と証拠の要件](https://github.com/SagaK-dev/SagaLLM/issues/22)
- 標準入出力の追加学習後も、合成検証18ケースで正答は0件。学習例の順序だけを変えた追試でも基準・通常順・対照順の3条件すべてが0/18。異なる6指示に対する生成ソースはそれぞれ3種類、2種類、1種類だった。[追加学習](https://github.com/SagaK-dev/SagaLLM/actions/runs/45164032104) · [同じ学習例での比較](https://github.com/SagaK-dev/SagaLLM/actions/runs/45167198398)
- 独立評価の候補6題には権利・既存データとの重複・問題仕様について第三者の確認が残る。公開問題の探索試験と、研究用の合成検証は別々に報告する。[独立評価の審査記録](https://github.com/SagaK-dev/SagaLLM/issues/36)

## 今回の測定条件

**工程2**　v0.17は同じ重みのままRoPE上限を384にする。testの固定30題はseed 47、コンパイル8題はseed 67。生成は標準プロンプト、greedy、最大170トークン。参照ソースと生成結果は`javac --release 17 -proc:none`で検査する。長さは元の指示と正解回答を合わせた予測位置数で、192以下と193〜384に分ける。損失は正解回答トークン（終端を含む）の加重平均。過去の採点は原本に残し、今回の追試に別の結果ファイルを発行する。

**工程3**　PR #44で既に使われた合成検証3種類（最小値、奇数の個数、ASCII小文字化）の各2変種（添字2・3）を使う。各正解回答に対し、同じ添字の他2種類の指示と、同種類のもう一方の添字の指示を当てる。指示部分を損失から除き、各組の `誤った指示の損失 − 正しい指示の損失` を比較する。正は正しい指示を優先したことを示す。絶対差が `1e-6` 以下なら同点。診断は教示された正解に対する尤度を測る。利用者が得る生成コードの正しさは工程4・5のI/Oで測る。
